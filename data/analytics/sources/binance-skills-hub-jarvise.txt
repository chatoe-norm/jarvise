What the Skills Hub is
----------------------
- Open, community-extensible marketplace of AI agent skills (SKILL.md + scripts)
  for Claude Code, OpenClaw, LangChain, CrewAI, custom agents. Node.js 22+.
- Upstream install is `npx skills add https://github.com/binance/binance-skills-hub`.
  Jarvise never runs this: it pulls every skill, including trading/wallet ones.
- Two categories:
  - Read-only: market data, token info, audits, rankings, signals, wallet views
  - Read + Write: transfers, swaps, limit orders (Agentic Wallet), CEX trading
- Binance MCP Server (Agent Native) trades Spot / Margin / Convert / Futures
  inside a dedicated Agentic sub-account. It is execution tooling.
- Upstream disclaimer: informational only, not investment advice, may be
  inaccurate or outdated. Jarvise treats every hub output as context, not signal.

Adoption matrix
---------------
ADOPT (read-only, no API key; via jarvise-binance-intel only)
- query-token-info: search, meta, dynamic (price, volume, holders, liquidity)
- query-token-audit: honeypot / rug / tax / contract-risk scan
- crypto-market-rank: token-rank, social-hype, smart-money-inflow
  (crowding / sentiment context only; never a trigger)
- binance-tokenized-securities-info: Ondo tokenized US stocks — list, meta,
  market status, per-asset status (earnings/dividend/split halts), dynamic
  (on-chain price + US fundamentals), kline. Covers the stocks/ETFs goal.
- academy-skill: Binance Academy glossary / courses / articles; risk
  education for leverage / borrowing / all-in intents. Never advice.

EXCLUDE (read-only but poor fit for slow, steady, capital-preserving doctrine)
- query-token-info kline: proxies through third-party host dquery.sintral.io.
  Use Binance Spot GET /api/v3/klines via `jarvise ingest` (SQLite) for CEX
  pairs, or the tokenized-securities kline for Ondo stock tokens.
- crypto-market-rank meme-rank and address-pnl-rank
- trading-signal (per-trade smart-money buy/sell events, BSC/Solana memes)
- binance-wallet-tracker, query-address-info, binance-leaderboard

DENY (can write, execute, move funds, or post publicly)
- binance (binance-cli: Spot, USD-S Futures, Convert, margin, earn, wallet)
- binance-agentic-wallet (transfers, swaps, limit orders, DeFi, x402 payments)
- binance-trading-signal (baw CLI strategy create/update/delete/backtest)
- binance-onchain-copy-trader
- meme-rush
- fiat, p2p, payment, onchain-pay
- square-post (public posting to Binance Square)
- sports-ai-analyzer (off-domain)
- Binance MCP Server / Agent REST (Agentic sub-account trading)

Parsing rules
-------------
- Numeric fields arrive as strings; convert with Decimal before arithmetic.
- All timestamps are Unix milliseconds UTC.
- Tokenized stocks: 1 token = multiplier shares. referencePrice = price / multiplier.
  US stock volume is in shares, not USD.
- Relative icon/report paths: prepend https://bin.bnbstatic.com.
- Search returns look-alike tickers (e.g. "BTCB" also matches "BTCBSC" at a
  tiny price). Always confirm chainId + contractAddress, then audit.

Doctrine mapping
----------------
- Audit riskLevelEnum HIGH, any hit detail with riskType RISK (honeypot etc.),
  or non-zero sell tax → veto → FLAT. LOW risk is "no known red flags", never "safe".
- Audit riskLevelEnum MID (upstream docs say MEDIUM; live API returns MID, e.g.
  BSC USDT = MID from a single "Mintable Detected" CAUTION hit) is not a veto
  alone: list each isHit detail; CAUTION hits lower confidence only.
- Rank / hype / smart-money inflow = crowding + sentiment context. Same rule as
  oscillators: never a standalone trigger. Extreme hype raises caution.
- Tokenized stocks: respect market status and per-asset pause/limit reason codes
  (earnings, dividends, splits, mergers). No thesis across a halt.
- Leverage / borrowing / all-in intents → Academy risk education + doctrine
  (fractional Kelly, stops >= 1.5x ATR, kill-switch). Jarvise is spot paper only.
- Structure first: hub data never replaces SQLite price-graph (OHLCV + ATR/EMA)
  or Gemini Notebook doctrine. Below confidence threshold → FLAT.

Secrets and env names
---------------------
- The hub `binance` skill reads BINANCE_API_KEY + BINANCE_SECRET_KEY and
  BINANCE_API_ENV. Jarvise uses BINANCE_API_KEY + BINANCE_API_SECRET for the
  P3 read-only GET /api/v3/account path only. Do not rename; do not use binance-cli.
- Hub auth rules worth keeping: never printenv/env or source secrets files,
  never echo credentials, never disclose key file locations.
- jarvise-binance-intel needs no keys at all.
